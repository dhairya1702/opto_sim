# VR procedure and interaction audit — 2026-10-27

Reviewed `7aaf957` on `vr-improvements`. The starting working tree was clean. This audit compares all 20 active Practice XR routes with their teaching pages, guided-step functions, procedure engines and recording paths, and inspects the shared runtime and consultation adapter. It proposes corrections; application behavior and clinical content have not been changed.

Evidence labels: **reproduced** means a temporary Vitest probe exercised the current implementation, including mounted controllers where stated. **source-confirmed** means the mismatch is directly visible in the implementation and teaching contract. Neither establishes clinical validity or physical Quest acceptance.

All findings below are P2 unless marked P3: they affect procedure fidelity, guidance, or consistency, but this review found no demonstrated data loss or consultation scoring corruption.

| ID | Finding and impact | Evidence and proposed correction |
| --- | --- | --- |
| F1 | **Browser-mirror recording bypasses the current XR validity check.** A completed cover observation or accommodative-facility count can be saved while the session is hidden. | **Reproduced with mounted controllers:** capture an observation, enter the answer, save the mirror's `record` callback, dispatch hidden visibility, then invoke it. Distance cover and OD facility records are saved. `CoverPracticeController.tsx:291` tests `active` but not `frameValid`; `AccommodationPracticeController.tsx:105` tests `live` only. The headset `PracticeLessonUI.tsx:116` submit wrapper already checks frame validity, so this is specifically an inconsistent mirror/direct-handler boundary. Gate the mutation itself, preserving completed captures for saving after recovery. Inspect equivalent direct handlers in Push-up, minus lens, NRA/PRA, Maddox, Thorington, motility and consultation; several also rely on the caller's gate. Those additional paths were not reproduced in this audit. |
| F2 | **Accommodative-facility guidance tells the learner to return to plus during a correct minus half-cycle.** Following that coaching can encourage a premature turn and lose a valid pair. | **Reproduced through the pure engine:** establish fixation, start, wait 1,500 ms, flip to minus. The run remains `running`, but `accommodativeFacilityGuidedStep` returns “Align plus flipper.” At `accommodativeFacilityProcedure.ts:172`, the plus-side setup check precedes the running-phase branch. Require plus only before starting; during timing, coach the current side and wait for its clear report. |
| F3 | **Second-direction vergence guidance reuses the first-direction baseline.** Vertical distance says “Hold the BU zero baseline” during BD; horizontal near says “Hold the BI zero baseline” during BO. | **Reproduced by completing the first direction and entering a valid second-direction baseline.** See `verticalFusionalVergenceProcedure.ts:248` and `nearFusionalVergenceProcedure.ts:332`. The engines correctly enter BD/BO, but the coach scans the original setup checks first. Derive orientation and baseline wording from the current direction and completed captures. Also make recovery guidance use the current direction after an interruption. |
| F4 | **Both cover modules omit the taught refractive-correction prerequisite.** Learners can acquire and record observations without fitting correction. | **Reproduced in mounted cover–uncover:** prepare the target and complete the cover sequence without touching the trial frame; recording becomes ready. `PracticeMode.tsx:257` teaches best correction and alternate cover inherits that setup. `CoverPracticeController.tsx:31` supplies only target sockets; its sampler and progression contain no correction check. Add the appropriate fitting socket, guided step, validity check and correction-change invalidation. Preserve the separate consultation case's authored unaided cover conditions. |
| F5 | **Worth retains fixation through a visibility interruption occurring between sampled frames.** A new patient report can be captured after recovery without a fresh fixation instruction. | **Reproduced in the mounted controller:** fit equipment, power the near target, give fixation; dispatch hidden then visible before the next frame. The coach remains on `elicit-near`, and asking produces a recordable report. `WorthPracticeController.tsx:43` clears pending entries only; the condition key at line 76 excludes tracking/visibility. Clear current fixation synchronously for tracking, visibility and teleport interruption, preserving completed reports and saved endpoint records. |
| F6 | **Worth's taught filter-cancellation check has no corresponding action or gate.** Fitting glasses alone satisfies the filter requirement. | **Source-confirmed alignment mismatch:** `PracticeMode.tsx:282` explicitly teaches checking that the filters cancel target colours. `xrWorthPractice.ts:11` checks only fitted glasses; the controller has no filter-check state. Existing tests deliberately assert the absence of that gate (`xrWorthLoop.test.ts:101`), so a passing suite cannot resolve the teaching mismatch. Decide with clinical review whether to restore the taught check or revise the teaching contract; update implementation, teaching, documentation and tests together. |
| F7 | **Worth's distance coach requests fixation while the target is off.** Its recommended action is disabled. | **Reproduced in the mounted controller:** save near, dock at distance, switch the target off. The coach reports `fixate-distance`, but the fixation action is disabled because setup is not ready. The near branch handles power; the distance branch at `xrWorthPractice.ts:77` does not. Add a power/setup recovery branch before distance fixation. |
| F8 | **Krimsky can skip the initial uncorrected reflex observation.** A neutral comparison can be captured directly without any preceding baseline evidence. | **Source-confirmed; pure capture probe reproduced direct acceptance.** `alignmentGuidance.ts:63` says to observe initial reflexes with no prism; `docs/binocular-vision-practice.md:154` additionally describes a 0.8-second baseline capture. `KrimskyPracticeController.tsx:153` calls a stateless neutral-endpoint check, and `xrKrimskyPractice.ts:62` has no baseline requirement. Represent the initial observation in shared procedure state. Reconcile the documented dwell and monocular-view presentation with the intended current design before choosing exact behavior. |
| F9 | **Hirschberg completion does not assess all the recording fields taught before entry.** A learner never has to identify the deviating eye or describe reflex displacement. | **Source-confirmed:** `PracticeMode.tsx:240` teaches eye, reflex direction, inferred deviation and approximate landmark. `HirschbergPracticeController.tsx:182` and `xrHirschbergPractice.ts:20` assess only deviation direction and amount. Add distinct observation fields or explicitly narrow the learning objective with clinician review. OD/OS should be independently recorded for abnormal findings. |
| F10 | **Alternating-cover prism recording copies instrument settings instead of collecting the learner's reading.** Completion cannot detect a misread prism power or base. | **Source-confirmed:** fields at `CoverPracticeController.tsx:32` ask only movement and deviation. At line 313, saved power/base/eye come directly from setup refs. The teaching at `PracticeMode.tsx:270` requires recording the neutralising prism. Retain the acquired neutral endpoint separately and collect blank learner-entered power/base for comparison, following the newer vergence modules' pattern. |
| F11 | **Near vergence facility lacks the step-by-step Guided XR experience offered by the other modules.** The generic pre-entry checklist also teaches increasing demand, separate blur/break and recovery, which describes measured vergence rather than this timed flipper procedure. | **Mounted probe confirms no guided bubble.** `VergencePracticeController.tsx` never reads attempt settings or derives a guided step. Its menu/help remains available, but it has no event-driven next-step coach or Guided/Test-specific disclosure. `PracticeMode.tsx:319` applies the generic checklist to facility. Give facility a dedicated shared procedure/coach for correction, near target, fixation, BO/BI clear responses, full pairs, timing and independent count entry; preserve neutral controls in Test. |

Documentation drift is a separate P3 issue. `docs/binocular-vision-practice.md:164` describes 14 Worth steps and isolated-filter confirmations; the engine exposes 12 steps and tests intentionally exclude filter confirmation. The same document describes explicit stereo classification while `StereoPracticeController.tsx:160` automatically classifies the selected patient response. Its Krimsky baseline claims exceed the current adapter. These differences need deliberate reconciliation; historical documentation is not evidence that a current gate exists.

The alignment changes involving clinical recording fields, correction requirements or examination sequence should follow the repository's clinical-review discipline. Do not change authored findings or numerical endpoints to make the implementation appear consistent. Review status remains draft.

Optimization opportunities are ranked by expected engineering value. These are source-supported opportunities, not measured FPS gains:

| Order | Opportunity | Concrete change and verification |
| --- | --- | --- |
| 1 | **Stop rediscovering the whole scene after every host update.** `useXRClinicRuntime.ts:303` has an effect without dependencies that traverses the scene. Thorington publishes fresh spatial state around 24 times/second at 72 Hz (`ThoringtonPracticeController.tsx:81`), and other hosts also update frequently. | Complete explicit registration of interaction roots; invalidate discovery only when scene topology changes. Keep current closures on registered objects and preserve late-mounted panels, modal priority and instrument selectors. Use existing `ray target audit` counters and input regressions to verify fewer scans without losing targets. |
| 2 | **Reduce raycast allocations and work before rejection.** `useXRClinicRuntime.ts:596` rebuilds and deduplicates candidates with `indexOf` on every ray hit, recursively intersects them, then filters invisible/ignored ancestry. | Cache a unique candidate array when registration changes, reuse hit arrays, and exclude whole hidden/ignored roots before intersection where selector behavior permits. Retain the current per-frame hit cache and fresh event-boundary sampling. Measure CPU time and allocations, including open findings boards. |
| 3 | **Avoid repeated report-material invalidation.** `XRPanelClip.tsx:14` depends on JSX `children`; each parent render can restore/reinstall shader hooks and mark all report materials `needsUpdate` twice. | Patch once per actual material lifetime; retain clipping matrices and sizes in stable uniforms. Handle replacement materials explicitly. Measure material versions/program checks and test clipping for moving headset panels. Do not assume every invalidation compiles a new GPU program. |
| 4 | **Separate physical sampling from React publication.** Thorington always calls `setSpatial` with a fresh object; consultation motility updates target state above a 6 mm movement threshold and dwell state above 40 ms (`XRConsultationController.tsx:536`). Push-up also creates fresh frozen setup/approach states each frame. | Keep exact movement/dwell in refs; publish meaningful phase/report changes immediately and stable display snapshots at a bounded rate. Preserve per-frame procedure sampling and interruption resets. Compare host render counts before/after in idle, moving, report and recording phases. |
| 5 | **Remove obsolete measured-prism branches from the facility-only controller.** `VergencePracticeController.tsx:20` defines `isPrism = kind !== "facility"` although its only allowed kind is `facility`; it still carries base indices, endpoint marking, unused values and branches. | Extract the timed facility engine and delete unreachable measured-vergence plumbing. Share safe low-level helpers, not procedure-specific interpretation. Verify premature turns, paired counting, deadline capture, interruption and released-tool recording. This is principally a maintainability improvement. |
| 6 | **Use actual headset measurements to select further GPU work.** Current build chunks include Three.js 703.96 kB and scene vendor 430.44 kB raw, but chunk size does not establish the source of frame drops. | Preserve existing lazy module loading, demand-rendered preflight, texture reuse, compact shadows and foveation. Measure frame time, draw calls, geometry/texture growth and text legibility on Quest before merging static geometry, instancing repeated meshes or reducing geometry detail. Optimize only measured hotspots. |
